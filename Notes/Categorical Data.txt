CATEGORICAL DATA

Categorical data is qualitative data that groups observations into categories based on shared characteristics.

Examples:
- Gender
- Nationality
- Blood Group
- Education Level
- Customer Satisfaction Rating

Unlike numerical data, categorical data uses labels rather than numbers.

------------------------------------------------------------
ENCODING CATEGORICAL DATA

Machine learning models cannot directly process text values such as:
- Dog
- Red
- London

Categorical values must therefore be converted into numerical representations before training. This process is called Encoding.

------------------------------------------------------------
FEATURE VECTOR AND DIMENSION

A Feature Vector is the numerical representation of data used by a model.
Dimension = Number of elements contained in a feature vector.

Examples:
Feature             Categories
Snowed Today        2
Skill Level         3
Season              4
Day of Week         7
Planet              8

Features with relatively few categories are called Low-Cardinality Features.

------------------------------------------------------------
VOCABULARY ENCODING

A Vocabulary is the complete list of valid categories for a feature.

Example:
Color Vocabulary
Red     → 0
Orange  → 1
Blue    → 2
Yellow  → 3
Green   → 4
Black   → 5
Purple  → 6
Brown   → 7

These numbers are only identifiers.

------------------------------------------------------------
WHY INDEX VALUES ARE NOT ENOUGH

Example:
Red     → 0
Orange  → 1
Blue    → 2
Purple  → 6

A model may incorrectly assume:
Purple > Blue > Orange > Red
or
Purple is six times Red.

Since these relationships do not exist, categorical data often requires One-Hot Encoding.

------------------------------------------------------------
NOMINAL DATA

Nominal Data consists of categories with no natural order.

Examples:
- Hair Color
- Gender
- Blood Group
- Nationality
- College Major

Common Encodings:
- One-Hot Encoding
- Label Encoding

------------------------------------------------------------
ORDINAL DATA

Ordinal Data consists of categories with a meaningful ranking.

Examples:
- Education Level
- Customer Satisfaction
- Product Ratings
- Class Rankings

Example:

Poor      → 1
Fair      → 2
Good      → 3
Excellent → 4

Common Encoding:
- Ordinal Encoding

------------------------------------------------------------
CATEGORICAL ENCODING METHODS

1. LABEL ENCODING

Assigns a unique integer to each category.

Example:
Red   → 0
Green → 1
Blue  → 2

Dataset:
Red
Green
Blue
Red

Encoded:
[0,1,2,0]

Best For:
- Decision Trees
- Random Forests
- XGBoost

Pros:
- Simple
- Memory Efficient
- Fast

Cons:
- May introduce false ordering

------------------------------------------------------------
2. ONE-HOT ENCODING

Creates a binary vector for each category.

Example:
Red   → [1,0,0]
Blue  → [0,1,0]
Green → [0,0,1]

Color = Blue
[0,1,0]

Best For:
- Nominal Data
- Low Cardinality Features

------------------------------------------------------------
3. ORDINAL ENCODING

Used when categories already have a natural order.

Example:
Low    → 0
Medium → 1
High   → 2

------------------------------------------------------------
4. TARGET ENCODING

Replaces categories with the average target value associated with them.

Example:
London → 1.0
Paris  → 0.0
Berlin → 0.0

Best For:
- High Cardinality Features

------------------------------------------------------------
5. BINARY ENCODING

Steps:
1. Assign Integers
2. Convert to Binary
3. Split Binary Digits into Columns

Example:
Red   → 10
Blue  → 01
Green → 11

Best For:
- High Cardinality Features

------------------------------------------------------------
6. FREQUENCY ENCODING

Replaces categories with occurrence counts.

Dataset:
Red
Green
Blue
Red
Red

Frequency:
Red   → 3
Green → 1
Blue  → 1

Best For:
- Large Datasets

------------------------------------------------------------
SPARSE REPRESENTATION

One-Hot Encoded vectors contain mostly zeros.

Example:
Blue

One-Hot Vector:
[0,0,1,0,0,0,0,0]

Sparse Representation: 2

Instead of storing the entire vector, only the non-zero position is stored.

Purpose:
- Memory Saving
- Faster Processing

------------------------------------------------------------
CARDINALITY

Cardinality = Number of unique categories in a feature.

------------------------------------------------------------
LOW CARDINALITY

Features with few unique categories.

Examples:
- Gender
- Blood Group
- Satisfaction Rating

Usually encoded using:
- One-Hot Encoding

------------------------------------------------------------
HIGH CARDINALITY

Features with many unique categories.

Examples:
- Product IDs
- Customer IDs
- ZIP Codes
- Email Addresses

Example:
P1001
P1002
...
P9999

Problems:
- Too many columns
- Higher memory usage
- Slower training

Better Methods:
- Target Encoding
- Frequency Encoding
- Binary Encoding
- Hash Encoding
- Embeddings

------------------------------------------------------------
CATEGORICAL OUTLIERS

Rare categories that occur infrequently.

Example:
Common:
- Red
- Blue
- Black

Rare:
- Mauve
- Avocado
- Lavender

Problems:
- Extra columns
- Overfitting
- Memory waste

Solution:
Group rare categories as:
OTHER
or
OUT-OF-VOCABULARY (OOV)

Example:
Mauve   → Other
Avocado → Other

------------------------------------------------------------
HIGH-DIMENSIONAL CATEGORICAL FEATURES

Features containing extremely large numbers of categories.

Examples:
English Words      500,000+
US ZIP Codes       42,000+
Customer IDs       Millions
Product IDs        Millions

Problems:
- High Memory Usage
- Slower Training
- Slower Prediction
- Overfitting

------------------------------------------------------------
EMBEDDINGS

Embeddings convert large sparse vectors into smaller dense vectors.

Instead of:
[0,0,0,0,1,0,0,0...]

Use:
[0.42,-0.18,0.91,0.27]

Advantages:
- Reduced Dimensions
- Less Memory
- Faster Training
- Faster Prediction
- Learns Category Similarities

------------------------------------------------------------
HASHING (HASHING TRICK)

Maps categories into a fixed number of buckets.

Example:
Red    → Bucket 2
Blue   → Bucket 5
Green  → Bucket 1
Purple → Bucket 2

When multiple categories share a bucket:
Hash Collision

Pros:
- Fixed Dimensions
- Memory Efficient
- Handles New Categories

Cons:
- Hash Collisions
- Less Interpretable

------------------------------------------------------------
HUMAN AND MACHINE LABELS

-------------------------------
GOLD LABELS
Labels assigned by humans.

Possible Issues:
- Human Error
- Bias
- Inconsistent Labeling

-------------------------------
SILVER LABELS

Labels generated automatically by machine learning systems.

Possible Issues:
- Misclassification
- Model Bias
- Labeling Errors

------------------------------------------------------------
INTER-RATER AGREEMENT

Measures how consistently different human raters assign labels.

Example:
Rater 1 → Dog
Rater 2 → Wolf
Rater 3 → Fox

More disagreement = Lower Inter-Rater Agreement

------------------------------------------------------------
FEATURE CROSSES

Feature Crosses combine two or more categorical features into a new feature.

Purpose:
- Learn feature interactions
- Help linear models capture non-linear relationships

------------------------------------------------------------
FEATURE CROSS EXAMPLE

Edge Type:
- Smooth
- Toothed
- Lobed

Leaf Arrangement:
- Opposite
- Alternate

Feature Crosses:
Smooth_Opposite
Smooth_Alternate
Toothed_Opposite
Toothed_Alternate
Lobed_Opposite
Lobed_Alternate

Example:
Lobed + Alternate
↓
Lobed_Alternate

------------------------------------------------------------
REAL-WORLD FEATURE CROSS EXAMPLE

Neighborhood:
- City Center
- Suburb

Home Type:
- Apartment
- House

Feature Crosses:
CityCenter_Apartment
CityCenter_House
Suburb_Apartment
Suburb_House

------------------------------------------------------------
DRAWBACK OF FEATURE CROSSES

Feature Crosses increase dimensionality.

Example:
Feature A = 100 Categories
Feature B = 200 Categories

Cross Size:
100 × 200 = 20,000 Categories

------------------------------------------------------------
CHOOSING THE RIGHT ENCODING

One-Hot Encoding
Best For:
- Nominal Data
- Low Cardinality

Label Encoding
Best For:
- Tree-Based Models

Ordinal Encoding
Best For:
- Ordered Categories

Target Encoding
Best For:
- High Cardinality

Binary Encoding
Best For:
- High Cardinality

Frequency Encoding
Best For:
- Large Datasets

Embeddings
Best For:
- Very High Cardinality

Hash Encoding
Best For:
- Massive Datasets
